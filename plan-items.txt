ROGUELIKE GAME - ITEMS IMPROVEMENT PLAN
=======================================

Goals:
1. Stop littering the maps with too many dropped items
2. Add an item quality system (same item type, different power)
3. Add more variants of the same item type (weapons, armor, consumables)
4. Let the player swap items from the inventory (real equipment system)

This plan is separate from plan.txt and plan-improvements.txt.

WORK RULES
----------
- [x] = done, [ ] = pending
- After each phase keep green: bun test, bun run typecheck, bun run lint,
  bun run build, bun run verify
- Core stays pure: src/core must not import src/ui or src/platform
  (enforced by tests/architecture.test.ts)
- All item rolls must stay deterministic from the run seed
  (floorCache RNG stream in src/core/floorCache.ts:26, game.battleRng)
- Save format changes require a SAVE_VERSION bump plus a migration in
  src/core/save.ts migrateSavedRun
- Prefer small commits per step

CURRENT STATE (audit)
---------------------
- ItemKind = potion | gold | sword | shield | torch | corpse. Inventory is a
  flat struct { gold, potions, torches, sword: bool, shield: bool }
  (src/core/items.ts:4-16).
- Map items are bare tiles: PlacedItem { x, y, tile }
  (src/core/mapgen/common.ts:23-27). There is no instance data, so quality
  and variants cannot exist today.
- Picking up a sword/shield permanently mutates player.atk/def and is
  one-shot ("You already have a sword", src/core/items.ts:47-56). There are
  no equipment slots and no swapping.
- Floor placement: count = rng.int(3,5) + min(depth,3) items, uniform over
  5 kinds (src/core/mapgen/common.ts:236-252), up to 8 identical items.
- Loot drops: EVERY killed monster pushes an item; 30% gold, otherwise a
  corpse (src/core/game.ts:204-210). With 3+depth monsters spawned per floor
  (src/core/entities.ts:181), corpses and gold pile up and are never removed.
  This is the main "too many items" source.
- Gold pickup adds exactly 1 (src/core/items.ts:41-43).
- Rendering is tile-index only (src/core/sceneBuilder.ts:58-59). Tile sheet
  is 8 columns, indices 0-23 used, 24-31 free (src/core/tiles.ts).
- Save: SAVE_VERSION = 2; isInventoryShape validates the flat struct;
  isEntityShape validates entities; floors serialize map.items verbatim
  (src/core/save.ts, src/core/floorCache.ts:63-70).
- Inventory UI is a static read-only list except drinking/lighting
  (src/platform/menuTree.ts:41-88); "i" opens it (src/platform/input.ts:74-84).
- Level ups (src/core/entities.ts:122-136) and skill points
  (src/core/game.ts:323-338) also mutate atk/def directly.

DESIGN DECISIONS
----------------
D1. Item instances: extend PlacedItem to
    { x, y, tile, kind, variant, quality }. Keep tile for rendering.
    Item definitions live in a data table ITEM_DEFS in src/core/items.ts:
    { kind, variant, tile, baseStat, minDepth, weight }.
D2. Quality tiers: common | uncommon | rare (3 tiers to start).
    Weapon atk bonus +0/+1/+2, armor def bonus +0/+1/+2, potion heal
    +3/+5/+8. Tier is rolled with a depth-weighted table.
D3. Variants per kind (depth-gated pools):
    weapons: dagger, short sword, long sword, battle axe
    armor:   buckler, iron shield, kite shield
    potions: minor potion, major potion
    torches: torch, bullseye lantern
    Each variant has its own tile + base stat; quality layers on top.
D4. Equipment slots: weapon + armor. Player stats become
    base (level + skill points) + equipment bonuses, recomputed by a single
    recalcStats() helper instead of mutating atk/def at pickup time.
    Add baseAtk/baseDef to Entity.
D5. Inventory: gold + consumable stacks keyed by (kind,variant,quality) with
    counts + carried equipment list (cap 6) + equipment { weapon, armor }.
    Equipping swaps the old piece back into the carried list.
D6. Drop budget: cap floor-placed items, weight the spawn table, make
    monster loot probabilistic, and cap corpses per floor.
D7. Quality visuals without new art per tier: color item names in menus and
    hints, and draw a small tinted pip on the map tile (new CellView field).

ACCEPTANCE CRITERIA
-------------------
- Average pickable items per floor <= 5 at depths 1-5 (was up to 8 placed
  plus ~1 corpse/gold per kill)
- No floor ever shows more than 6 corpses
- At least 4 weapon variants and 3 armor variants exist, depth-gated
- Same-variant items differ by quality tier with visible stat and color
  differences
- Player opens inventory with "i", equips a carried weapon, the previous
  weapon returns to the inventory, and ATK updates correctly (swap)
- Old v2 saves load and migrate without crashing

RISKS
-----
- Changing placeItems RNG stream changes every floor layout for a given
  seed. Acceptable: existing saves carry floors explicitly; new runs differ.
- Stat recalculation touches level ups, skill points, and save/load.
  Centralize in recalcStats to avoid drift.
- MenuNav memory keys are index-based; item lists shrink/grow after equip.
  Use stable instance ids (step 3.5) to avoid selection jumps.
- Tile sheet has only 8 free slots (24-31). If more variants are needed,
  grow rows in tools/make-tiles.ts; SHEET_COLS stays 8.
- Inventory cap of 6 is a design choice; tune during phase 5 playtest.
